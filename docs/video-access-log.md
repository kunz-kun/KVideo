# 管理员视频播放记录

本功能在网页 `/player` 播放器触发原生 `playing` 事件时，记录视频实际开始播放。打开页面、仅加载详情、自动播放被浏览器拦截或加载失败均不会记录。暂停后继续、缓冲恢复和重试播放同一视频/来源/集数不会重复记录；切换到另一集或来源并开始播放会新增记录。不代表已看完，不统计原生电视客户端、IPTV 或投屏后仅在远端设备触发的播放。

## 部署

沿用现有 Cloudflare Pages 的 `npm run pages:build` 和 `.vercel/output/static`。新增接口使用 edge runtime，无需新依赖。

推荐在 Cloudflare 创建独立 D1 数据库，执行 `migrations/0001_video_access.sql`，然后在 Pages 项目绑定为 `VIDEO_ACCESS_DB`。生产和预览环境都需要相应绑定及数据表；建议预览使用独立数据库。D1 使用现有账号体系，不要求启用托管账号或 Redis。

如果已有 Upstash Redis，也可使用 `UPSTASH_REDIS_REST_URL` 与 `UPSTASH_REDIS_REST_TOKEN`（写权限）。已配置 D1 时优先使用 D1，否则回退到 Redis。Redis 凭据只属于服务端，不要使用 `NEXT_PUBLIC_` 前缀。

必须启用现有管理员登录体系。已有账号配置可以沿用；否则需配置 `ADMIN_PASSWORD`，生产环境推荐同时设置 `AUTH_SECRET`。无登录状态不会显示日志；没有管理员登录的部署无法查询日志。账号角色为 `admin` 或 `super_admin` 才能查看，即便给普通用户额外的数据管理权限，也不能读取日志。

重新构建部署后，以管理员身份进入“设置”，在“账号设置”下查看“视频播放记录”。可按完整 IP、片名关键词查询，每页 50 条。未配置数据库会显示明确提示。设置 `VIDEO_ACCESS_LOG_ENABLED=false` 可以停止新增记录。

## 数据和权限

- 存储 IP、视频 ID、片名、集数、来源、是否高级模式、服务端时间；不保存播放 URL、账号姓名或密码。
- IP 只在 Cloudflare 请求运行时从 `CF-Connecting-IPv6` / `CF-Connecting-IP` 获取；不接受请求体的 IP 或 `X-Forwarded-For`。本地 Node 环境无法采集生产访问 IP。
- 管理查询接口 `/api/admin/video-access` 验证签名登录 cookie、30 天有效期及当前账号角色，拒绝未登录、普通用户、已删除或已降级管理员。响应使用 `private, no-store`。
- 写入接口 `/api/video-access` 要求同源 JSON；启用站点登录时要求用户已登录。每 IP 每分钟最多 60 条。浏览器只负责上报视频元数据，这些内容不是不可伪造的审计证据。
- 保留最近 30 天、最多 10,000 条；新增时原子清理旧数据，查询始终排除过期记录。D1 在无新增时仍可能物理保存过期记录，但不会展示；需定时清理时可额外配置 Cron。Redis 在无新增 30 天后整个集合自动过期。
- 日志写入失败不会阻断视频播放。浏览器屏蔽上报、断网或超限可能产生漏记；历史记录不能回溯补齐。
- IP 是网络出口地址，多人共享网络或使用 VPN 时无法据此判断具体个人。

## 上线验收

1. 管理员只打开视频 A（阻止自动播放）时不产生记录；点击播放后出现一条；暂停再继续仍一条。切换到下一集并开始播放后新增第二条。
2. 普通用户设置页不显示记录；直接 GET 管理查询接口返回 403，未登录返回 401。
3. 片名及完整 IPv4/IPv6 筛选、分页正常；管理员降级或删除后旧 cookie 无法继续读取。
4. 数据库不可用时播放不受影响，管理员界面显示读取失败。

采集 IP 和视频访问行为的说明应加入站点现有隐私说明；记录默认仅站点管理员可见。
